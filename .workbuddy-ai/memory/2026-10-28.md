# 2026-10-28

## WebGame 工作区：朗读 · 跑马灯 静态页（已交付）

**需求**：纯静态网页，Android/iOS 可用，可部署 GitHub Pages。两块功能：①输入文字调用本地 TTS 朗读；②输入文字全屏跑马灯。

**技术决策**
- 零依赖、零构建、经典 `<script>`（非 ESM）—— 保证 `file://` 双击也能跑
- TTS 用 Web Speech API `speechSynthesis`，调系统语音引擎（=「本地 TTS」）
- 跑马灯用 rAF + `translate3d` 逐帧位移，非 CSS animation；轨道按视口复制 N 份
  （`N = ceil(视口/单份尺寸)+1`），`offset % 单份尺寸` 回绕实现无缝循环
- iPhone Safari 不支持任意元素 Fullscreen API → 用 `position:fixed; inset:0` 浮层做伪全屏，
  真正的全屏体验靠「添加到主屏幕」+ manifest standalone

**关键实现细节（踩过的点）**
- iOS 首次 `speak()` 必须在用户手势调用栈内 → play 里同步调用，不用 setTimeout
- Chrome/Android 语音列表异步加载，`voiceschanged` 不一定触发 → 250ms × 20 次轮询兜底
- 逐句切分（`。！？!?；;\n…`），超 90 字硬切；不合并句子，否则进度条失去意义
- 看门狗兜底 onend 不触发（注意：strict mode 下 `arguments.callee` 会抛错，必须用具名函数）
- 长文本对象要持引用（`currentUtt`），否则 iOS 上可能被 GC 导致朗读中断

**产出文件**：index.html / assets/css/app.css / assets/js/{app,tts,marquee}.js /
assets/img/icon{,-180,-192,-512}.{svg,png} / manifest.webmanifest / .nojekyll /
tools/make-icons.py / README.md

**验证方式**：本地 `python -m http.server` + Playwright(chromium, iPhone 13 模拟) 实测，
console 零错误，跑马灯位移递增、暂停冻结、纵向+LED 正常、TTS 状态机 1/3→3/3 推进正常。

**图标生成**：本机无 Pillow，用纯标准库手写 PNG 编码器 + SDF 抗锯齿生成（tools/make-icons.py）。

## 追加：跑马灯增加「横屏 / 竖屏 / 跟随设备」

**方案**：不用 `screen.orientation.lock`（iOS Safari 完全不支持，Android 仅原生全屏下可用），
统一走**几何旋转**：需要与设备实际朝向不同时，把画框宽高对调（`width=视口高`、`height=视口宽`）
再 `rotate(90deg)` 居中。旋转后画框正好覆盖视口，`clientWidth/clientHeight` 即为逻辑尺寸，
`build()` 无需改动。控制条一起旋转（画框内），落点在设备角落，避开刘海。

**结构变更**：`.stage` 下新增 `.stage-frame`，包住 `.stage-view`（内容）与 `.stage-ui`（控制条）。

**顺手修掉的真实缺陷**：浏览器进入全屏后**只渲染全屏元素子树**，挂在 `body` 上的 Toast 不可见
（之前「请先输入文字」这类提示在全屏里根本看不到）。改为 `NS.toast` 检测舞台是否打开，
自动把提示条挂到 `.stage` 内部，退出后挂回 `body`。同时给 Toast 加了 1px 半透明描边提升深色底对比。

**状态**：`S.orient = 'auto' | 'landscape' | 'portrait'`，随 `wb.mq` 持久化。

**验证**：Playwright 覆盖 7 个场景（竖屏设备下横屏/竖屏/自动、横屏设备下强制竖屏、旋转+纵向滚动叠加），
console 零错误，frame 尺寸与 transform 均符合预期。

**踩坑**：控制条 3.2s 自动隐藏后 `pointer-events:none`，且点击是**切换**语义，
自动化测试要先判断 `is-ui` 类再决定是否补点一次。

## 追加：修复「播到末尾就重头播」+ 新增「重复间隔」

**用户反馈**：「头尾相接的播放，不要播到末尾就重头播，头尾之间可以加空白」。
排查后确认**是真实缺陷**，不是视觉偏好。

**根因（重要，别再犯）**：轨道用 `justify-content: center` 居中，轨道比视口宽时左右**各**溢出
`(N·cycle − 视口)/2`，一半余量被左侧吃掉。原公式 `N = ceil(视口/cycle) + 1` **少一份**，
位移到周期末尾时视口右半边没有内容 → 露出空白 → 下一帧回绕，读起来就是「跳回开头重播」。
**正确条件：`N ≥ 2 + 视口/cycle`，即 `N = ceil(视口/cycle) + 2`。**

**周期测量改用副本间距**：不再用单份 `getBoundingClientRect().width/height`，改为取两份副本
中心点的**欧氏距离**。原因：① 尺寸与实际排布间距可能不一致（纵向曾差 0.22px）；
② 欧氏距离对旋转是刚体不变量，画框旋转 90° 时依然成立。

**新增 `S.gap`（重复间隔）**：0–1200px，默认 200，UI 滑杆在「字号」下面。
`build(keepPhase)` 支持保留相位 —— 改间隔/字号/方向重建时用 `offset % cycle`，不跳回开头
（内容严格周期重复，整周期位移视觉不可见）。

**验证方法（可复用）**：Node 手写 PNG 解码器（zlib + 逐行反滤波），对「offset=0」与
「offset=−cycle」两帧做逐像素比对。横向 **0 差异像素**；纵向 1.87%、maxDelta 159，
确认为 0.22px 亚像素重采样（肉眼一致），非内容错位。四方向 × 间隔 0/1200 共 8 组回归通过。

**教训**：flex 居中 + 超宽子元素时，「复制填满视口」的份数公式必须把居中产生的左右双向溢出算进去。
